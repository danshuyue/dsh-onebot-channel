## 一、阻断项

1. `poke-sim` HOME 污染：属实。给 `tests/poke-sim.mjs` 增加独立临时 HOME、白名单配置和退出清理；直接运行结果为 60 过 / 0 败。
2. `npm test` 可能修改真实配置：属实。`package.json` 的 `test` 使用 `tests/run-isolated.mjs`；runner 给每个测试开 Node 子进程，设置 HOME、USERPROFILE、TMPDIR、TEMP、TMP，并在结束后清临时根目录。`voiceout-sim` 自己用 `mkdtemp` 建唯一临时根，忽略外部传入的目录环境变量；变异测试把系统临时目录导向自身随机 sandbox，并用保护哨兵验证不递归删除调用方指定目录。
3. 收藏表情假成功：报告所述“正文存在时失败分支必达不了”不成立。正文发送若失败会先抛错；只有收藏表情失败且没有成功正文/其他消息时才应报失败。保留当前逻辑；现有 face-pick 测试覆盖正文成功但收藏失败按部分成功、纯表情发送失败抛错。
4. 任意本机语音路径：属实且为安全问题。增加 `voiceOutputDir` 设置和设置页控件；发送前对配置根与目标文件做真实路径 containment 检查，拒绝目录外文件与链接逃逸；空目录禁用本机读取。另对内容签名、大小、目标白名单做校验，并限制每个目标每分钟 5 次。语音输出目录是用户配置的信任根，不是来源登记表。
5. 并发 @ 顺序：原报告把问题限定在 win=null 的分支；当前入口已对同群 @ 使用 Promise 队列，窗口开启与关闭时均串行。WS 处理在第一次 await 前同步入缓冲，因此复核提出的“空缓冲触发历史请求，后来的 @ 越过先来者”不适用于当前路径。`window-batch-sim` 覆盖未开窗/关闭窗口串行和同轮 poll 多 @ 顺序。

## 二、建议项

1. 主动搭话提示时间：属实。`composeNudge()` 以 `max(lastIncomingAt,lastProactiveAt)` 计算最近互动，`proactive-sim` 覆盖主动说话后采用较近时间。
2. 通知冷却并发竞态：报告不成立。`notifyTurn()` 同步检查并写入冷却时间，之后才进入发送 `await`；同一 JS 事件循环中的并发调用不能同时通过。通知发送失败也会被吞并记录。
3. 只读工具误判已发送：报告不成立。自动转发检查的是本回合 `tool/call` 名称 `qq_send`，不会将 `qq_wait` 等只读工具当作已发送。
4. 过旧 seq 静默丢弃：属实，现有逻辑拒绝旧消息并写 `skip stale seq` 日志，批处理测试覆盖。
5. 非法窗口时间永久不关闭：属实，窗口巡检将非法/负值回退到 idle 120000ms、max 600000ms；`window-batch-sim` 覆盖 NaN、负值和零语义。
6. 最近已投递集合取走即清：在同一 poll 批次中有共享 `recentlyDeliveredIds` Set；窗口循环投出的消息也会进入最近投递身份账本。`window-batch-sim` 覆盖两条连续 @ 不重复带入同一批旧消息。不同 WS 事件间依赖 `lastDeliveredSeq`，尚无已复现缺陷，不新增时间窗缓存。
7. `merge.js` 未改：非功能缺陷。报告描述应指向 `window.js` 中的实现；不为迎合文字而改动 `merge.js`。
8. 语音/戳的小口径：UIN 走 `normUin`，消息 id 做 BigInt 与安全整数校验，音频检查签名和目标频控。另复核发现 AMR/AMR-WB 的合法 LF 头比较有误，已修正为实际换行并加入两种头的回归测试。
