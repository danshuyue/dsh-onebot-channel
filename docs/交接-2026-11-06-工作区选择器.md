### 2.1 修的是什么缺陷

用户原话：「当前插件需要配置绑定的工作区**和会话**，但是会话来源工作区是默认写死的，以前忘记改了。
现在要在配置中提供选择工作区的功能。就像智能体团队配置绑定工作区一样。」

**根因**：`lib/config.js` 的 `DEFAULTS.workspaceCwd` 写死成 `D:\DSH workspace\QQ对话`，
而这个路径**在本机根本不存在**。

后果链：
1. `lib/sessions.js:56` `const want = String(getConfig().workspaceCwd ?? '')` → 用它筛会话
2. 筛出来是空的 → 设置页「N 个可选会话」**永远是 0** → 用户根本没法绑定任何会话
3. 而且这个值不只筛会话，还是「收到的图片」副本目录的根
   （`lib/images.js:305` / `lib/collect.js:452` 都 `join(config.workspaceCwd, '收到的图片')`）

**真实数据源**：`~/.dsh/storages/workspace.json`，`unit.version` 是 **2**，
数据在 `tables.workspaces`，每项 `{ path, title, sessionIds[], createdAt, updatedAt }`。
本机现有 15 个工作区，与 QQ 相关的是
`DSHQQ对话` | `D:\Yansunsky\Desktop\文本\DSHQQ对话`。

### 2.3 三个值得记住的设计判断

**① 自愈的兜底目标只能是 `DEFAULTS` 里那个，不能「注册表里随便挑一个」。**
早先版本写的是「挑会话最多的那个」，在这台机器上选出来是 `CreateCMPOR`（29 个会话，
一个 Minecraft 模组工作区）—— 跟 QQ 毫无关系。而这个值还是图片目录的根，
**挑错等于悄悄把以后收到的图全搬到别的工作区里去**。宁可不改，也不能改错。

自愈的三条纪律：
- 只修「配了但注册表里没有」的，**空串不碰**（空串是用户主动选「不筛工作区」）
- 注册表读不到、或默认工作区也不在注册表里 → **原样保留**，绝不凭猜测改
- 修完写回配置文件并记一行日志，别让「值自己变了」变成灵异事件

**② `/save` 的工作区校验必须排在所有赋值之前。**
写这个功能时真踩过一次：`routes` 先赋值、工作区后校验，于是请求虽然返回 400 了，
**内存里的绑定表已经变了**。`saveConfig()` 没跑，但 `getConfig()` 是模块单例，
下一次任何写盘都会把它带下去。
`tests/workspace-picker-sim.mjs` 的「被拒的请求没有顺手把 routes 也改了」就是钉这条的。

**③ 工作区不跟「保存」按钮走，只由选择器单独提交。**
两条理由：① 它要先按注册表校验，跟着保存按钮走的话，用户改个「分条字数」也会被 400 拦住，
而报的还是工作区的错 —— 没人能想到这两件事有关系；
② 换工作区本来就要立刻刷新会话列表，跟「保存后再生效」是两种手感。

## 3. 项目全貌（下一个会话开局用）

### 3.1 三条主链路

```
【入站】QQ → WS/轮询 → poll.js 处理 → deliver.js → agent.followup 唤醒会话
                                    ↓
                              state.js 记游标 / merge.js 合并 / images.js 转图

【回合】会话里模型跑一回合，可能调 qq_send / qq_pass / qq_close / qq_wait

【出站】模型回复 → outbound.js 队列 → split.js 分条 → onebot.js 唯一出口
                                                  ↓
                                   allowlist 白名单 → blocked 封禁 → sensitive 审计
```

**对话窗口是一条分叉，不是第四条链路**：

```
群消息进来 → handleGroupMessage
   ├─ 带 @  ────────────→ 直接 deliver（立刻进会话）  ← 会开窗 / 会建立门控
   └─ 不带 @ 且窗口开着 ─→ queueWindowMessage → pending
                              ↓ 攒够 3 条 或 满 8 秒（且门控已释放）
                           deliverWindowBatch → deliver
```

⚠️ **两条路的节奏完全不同，这是「顺序错乱」类缺陷的总根源**：带 @ 是同步唤醒
（`agent.followup`），不带 @ 要等攒批。`deliver` 本身**没有任何串行化**，
所以顺序完全靠 `window.js` 的 `batchHolds` 门控维持。

**关键约束**：所有出站都走 `onebot.js` 的 `callOneBot`，闸门就挂在那一个函数上。
想加新的发送路径，**必须**从 `callOneBot` 走，否则绕过白名单。

### 3.2 加配置项的标准动作（4 处，漏一处测试会红）

1. `lib/config.js` → `DEFAULTS`（**唯一真相源**）
2. `lib/api.js` → `publicConfig()` 暴露 + 归入 `NUMERIC_FIELDS` / `BOOLEAN_FIELDS` /
   `STRING_FIELDS` / `ARRAY_FIELDS` / `ENUM_FIELDS`
3. `lib/client.js` → `setTunables({...})` 加初始值 + 渲染控件
4. `tests/ui-wiring.mjs` → 若故意不给控件，加进 `DELIBERATE` 白名单并写理由

`ui-wiring.mjs` 会查：死配置（有默认值无人读）、可写字段是否都有控件、
API 暴露字段是否都在 `DEFAULTS` 里、白名单里有没有已删除的键。
**它比人眼可靠，别跳过。**

## 6. 本机特有的坑

1. **shell 写不进 `.git`：是低完整性令牌压住了 ACL，不是 ACL 缺授权**（2026-11-06 实测纠正）。
   `.git` 的 ACL 里本就有 `小瓜\Yansunsky FullControl`，真正拦路的是沙箱给的
   `Low Mandatory Level`（完整性级别压过 ACL）。**解法：给这一条命令提权**
   `sandbox_permissions: danger-full-access`，`git add` / `git commit` 一次就过。
   宿主文件工具（write/edit）也能写。
   ⚠️ `git add` 报 `Unable to create '.git/index.lock': Permission denied` 时**不是残留锁，别删 lock**。
   ⚠️ 也别绕去 IDE 终端：本机 idea MCP 工具没暴露给 agent，要用得先在 profile 配

4. **`git ls-tree` 默认转义中文路径**：加 `-c core.quotepath=false` 才是原始路径。
