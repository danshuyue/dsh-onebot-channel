## 4. 设计要点（改之前必须知道）

### 4.1 四档是「提示词 + 工具可见性」，不是运行时判断

**「这句话适不适合用语音」是语义问题，代码判不了。** 所以：

| 档 | `qq_tts` 注册？ | 系统提示词 |
|---|---|---|
| 禁用 | ❌ **不注册**（schema 不生成） | 不提语音 |
| 被动 | ✅ | 「除非你要求，否则不发」 |
| 自由 | ✅ | 「你自己判断」 |
| 主动 | ✅ | 「尽量都用语音」 |

「禁用」档**不能**做成「注册了但调用时报错」——模型会换个写法反复试，白烧 token
（这是 `tool.js` 文件头记过的教训）。

### 4.2 `voiceOut` 由 `voiceMode` 单向推导

`tool.js` 内部仍按 `features.voiceOut` 判断「`qq_send` 的 `voice` 参数在不在 schema 里」。
`config.js` 的 `deriveToolFeatures()` 从四档算出它。**只单向**：
不许反向写回 `voiceMode`，否则两个真相源会打架。

### 4.3 额度是**预扣**的

调 API **之前**扣，失败退回（钳到 0）。所以：
- 超额度时**零网络请求**（`tts-quota-sim` 专门断言这条）
- 失败不白扣一次
- 退款不钳 0 会让 `used` 变负 → 之后**所有请求都被放行**，额度闸等于失效

⚠️ **账本在内存里，重启 DSH 会重置当天额度。** 这是明确接受的代价
（比多写一个状态文件、处理并发写和损坏划算）。

### 4.4 全局串行队列

Breeze Free 档 `max_concurrent_generations: 1`（实测），GPT-SoVITS 是单进程 uvicorn。
所以 `tts.js` 有个模块级队列，所有合成串行。

⚠️ `chain = run.then(() => {}, () => {})` 这一行是**关键**：
不吞异常的话，一次失败会让整条链变 rejected，之后所有合成**瞬间全失败**。

## 5. 会咬人的坑（本会话实测的）

### 5.1 GPT-SoVITS 的接口形状和三份文档都不一样

`E:\AI\文转语音\GPT-SoVITS-api-v1-接口文档.md` 描述的是 `api.py` 那套**旧 REST**
（`refer_wav_path` / `prompt_text` 那套命名）。而 9872 端口跑的是 **inference WebUI**：

```
POST <base>/api/inference
body: {"data": [<23 个位置参数>]}
resp: {"data": [{path, url}, seed]}     ← 不是音频字节！
```

而且 `ref["file"]` 是 **Gradio 的 FileData 对象** `{path, meta:{_type:'gradio.FileData'}}`，
`path` 必须是**参考音频先 multipart 上传到 /upload 之后**服务端给的路径。

**本会话踩过两次**（都写进了 `tts.js` 的注释）：先按 v1 文档写了 15 个参数；
又以为 `ref["file"]` 是路径字符串。**照 `gptsovits_mcp_server.py` 抄，别照文档。**

⚠️ 9872 当时**没在跑**，所以本机引擎这条**只做了语法和形状验证，没做真机烟测**。

### 5.2 沙箱的写权限是分层的

| 操作 | 结果 |
|---|---|
| `write` / `edit` 工具 | ✅ 能写工作区 |
| `node -e "fs.writeFileSync(...)"` | ❌ EPERM |
| `rm` / `del` / `unlinkSync` | ❌ EPERM（连自己刚建的临时文件都删不掉） |
| `mkdtemp(系统 Temp)` | ❌ EPERM |
| `mkdir(DSHPlugins/.tmp-test/...)` | ✅ **唯一能建目录的地方** |

所以：
- 变异验证**不能让脚本改 `lib/*.js`** → 改成「复制到临时目录再改」（`tts-mutation.mjs` 的做法）
- 测试的隔离 HOME 不能 `mkdtemp(tmpdir())` → 用 `tests/isolated-home.mjs`
- **临时文件删不掉** → 只能 `write` 工具清成空壳（本会话留了 5 个，见 §3 末尾）

### 5.3 真机烟测抓出一个测试没覆盖的 bug

`writeVoiceFile()` 原来用 `toISOString().replace(/[-:T]/g,'').slice(0,15)` 拼时间戳，
`toISOString()` 的毫秒点没被去掉，`slice(0,15)` 正好把它切进文件名：

```
tts_20261106180834._b89bd8.wav      ← 中间那个 `._`
```

**所有单元测试都是绿的**（假 fetch 的产物能写盘、能被 sniff 成 WAV）。
只有真跑一次才看得见。已修（改用 `getFullYear()` 逐个取，顺便变成**本地时间**），
并补了 `tts-breeze-sim` 第 5 节断言文件名格式。

⇒ **教训：`sniffAudio` 能过 ≠ 文件名/落盘没问题。真机跑一次只要 4 秒。**

### 5.4 `sensitive.js` 原来认不出 Breeze 的 key

实测（真实 key 形状）：

```
裸 key                          → 漏
api key: brz_...（带空格）       → 漏
API KEY = brz_...               → 漏
key: brz_...                    → 漏
the api key is brz_...          → 漏
```

两个根因：关键词是 `api[_-]?key`（**不允许空格**），且裸 `brz_` 不在特征库里。
语音功能上线后模型手里就攥着这个 key —— 这条必须一起修，已修。

**修的时候又发现第三个漏**：`api key is xxx` 这种英文句型也漏（连接词只有 `[:=：]`/`是`/`为`）。
但直接把 `is` 加进连接词会让 `this key is important` 误伤，所以 `is` 是**单独一条更严的分支**
（要求后面 ≥16 位字母数字且非纯小写）。

### 5.5 变异验证自己也会漏

第一版 `tts-mutation` 里「删掉 `api\s+key`」这个变异**一直没被抓住**，
因为 `brz_` 形状规则把带 key 的用例全接住了 —— 测的其实是前缀规则。
改法：`sensitive-breeze-sim` 的「1b 节」**必须用不带已知前缀的串**
（`key: abcdefg…`、`the api key is qqqqwwww…`）。

同理「退款不钳 0」这个变异**最初也漏网**，补了「退款后仍拒绝超额请求」才抓住。

## 9. 0.19.1 补丁：分条间隔（2026-11-07 同日晚）

### 9.1 用户报的症状与真实原因

「两条信息之间会连续发消息，加个间隔更好。」

查下来**参数本来就有**（`splitDelayMinMs: 200` / `splitDelayMaxMs: 700`），但有两个问题：

| 问题 | 说明 |
|---|---|
| **找不到** | 它在「高级」里。人报「说话太急」会去「对话节奏」找手感，不会翻「高级」。**找不到的配置等于没有。** |
| **两种意图都表达不清** | 算式是 `min + min(max-min, 字数×12)`。想固定就得同时改两个值；而 `max` 把按字数的增长**截断**了 —— 实测 40 字就封顶 700ms，再长也不等更久。 |

40 字封顶 700ms，对一段长回复来说就是「几乎连着发」——这正是用户感受到的东西。

### 9.2 改成了什么

一个模式 + 一组数值：

```json
"splitDelayMode": "fixed",        // fixed | perChar
"splitDelayMs": 800,              // fixed 模式：每条等多久（0 = 立刻发）
"splitDelayPerCharMs": 120,       // perChar 模式：每字多少毫秒
"splitDelayMaxCapMs": 3000        // 上限，只压最终取值；0 = 不封顶
```

**默认 `fixed 800ms`**：800 是「明显不是在连发、又不至于让人等」的位置。

两种模式都加了 **±15% 抖动** —— 固定间隔不加抖动的话，一串等间隔的消息比连发还像机器人。

### 9.3 位置也挪了

从「高级」挪到**「对话节奏」**，新卡片叫「分条间隔」。
理由同上：这是「说话手感」，和那一栏的主题一致。

### 9.4 迁移

老配置（`splitDelayMinMs`/`MaxMs`）会自动迁移成 `fixed` + **区间中位数**
（200/700 → 450ms），并清掉两个退役键。

为什么取中位数而不是直接换成 800：**「我什么都没改，间隔却变了」是最让人困惑的**。
取中位数等于保留他现在的体感；想变，他自己会去调。

⚠️ 只在 `splitDelayMs` **不存在**时迁移 —— 已经设过的不动。

### 9.5 踩到的坑（值得记）

**`maxCapMs: 0` 被当成「上限 0 毫秒」而不是「不封顶」。**

原来写的是 `clampNumber(options.maxMs, 1, MAX, 0)`，而 `clampNumber(0, 1, …)`
会先把 0 抬到 1 —— 于是「不封顶」变成「上限 1ms」，间隔直接归零。

**单测当时没覆盖 `maxMs: 0`，所以一直是绿的。** 是端到端验证抓出来的
（配置写 `perChar 100ms/字`，实测间隔只有 14ms）。

修法与断言都补进了 `tests/split-delay-sim.mjs` 的「4b 节」，并做了变异验证
（把「先 clamp 再判 0」放回去 → 11 条断言变红）。

### 9.6 端到端验证结果（不是单测）

| 模式 | 配置 | 实测间隔 |
|---|---|---|
| fixed | 300ms | 264ms / 294ms ✅（±15% 抖动） |
| perChar | 50ms/字，三段 8/20/10 字 | 994ms / 542ms ✅（按**即将发的那条**算） |

⚠️ 注意间隔是按**即将发送的那一条**的长度算的，不是前一条。
