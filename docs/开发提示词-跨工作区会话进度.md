# 跨工作区会话进度 + QQ 焦点路由 —— 施工方案

> 2026-11-05。前置调研见工作区根目录 `QQ-跨工作区会话进度-调研笔记.md`。
> 本文是**动手前的最后一版方案**，实现时以本文为准；偏离之处必须在这里补注理由。

---

## 0. 先回答两个架构问题

### 0.1 「由一个会话统一管理」还是「最近会话兜底」？

**都不是。** 这两种都是在赌，只是赌的东西不同：

| 方案 | 实质 | 为什么不要 |
|---|---|---|
| **总台会话**（一个会话代理全部工作区） | 所有 QQ 消息进总台，总台自己查进度、自己转发 | ① 总台不是那个会话，它只能转述，永远比直接对话慢一层；② 每句话先烧总台的 token；③ 总台上下文会被别处的正文灌满，几十条就漂移；④ 真正需要「让那个会话干活」时还是要转发，等于绕远 |
| **最近会话兜底**（谁刚说话就回给谁） | 按活跃度自动改指针 | 现有 `sessionCandidates()` / `fallbackToLiveSession` 就是这条路，插件自己的注释写着「消息凭空进了别的对话」。48 个工作区并行时，「最近」是掷硬币 |
| **内容推断**（看你说的是什么事） | 让模型判断这条属于哪个会话 | 最危险：误判时**没有任何提示**，消息静默进错会话，那头的模型还认真干活。代价不对称 |

**采用：显式指针 + 引用即路由 + 默认绑定兜底，永不推断。**

三条规则，按优先级：

1. **你引用（quote）了某条机器人消息 → 就回给发出那条消息的会话。** 免记忆、免输入、零歧义。
2. **你 `/去 <编号>` 切过焦点 → 后续消息进那个会话。** 编号来自 `/进度` 列表，10 分钟内有效。
3. **都没有 → 走配置里 `routes[target].sessionId` 的默认绑定。** 行为与今天逐字一致。
4. **三条全落空（例如默认会话被归档）→ 不投递，回一句话告诉你去 `/进度` 挑。绝不兜底到别的会话。**

「总台」想要的两件事其实可以拆开、各自做得更好：
- **汇总视图** → 就是 `/进度`（只读、零 token、可以随时问）
- **一处发话多处可知** → 就是下面 §5 的变更推送（带会话标签）

### 0.2 「怎么区分某条 QQ 回复是给哪个会话的」

分两个方向，都有答案，且**都不靠猜**：

**方向 A：我的消息该进哪个会话**（入站路由）
- 引用某条机器人消息 → 那条消息的发送者会话（`onebot.js` 已有 `replyTargetOf()` 解析 `reply` 段，目前只用于窗口判定，复用即可）
- 当前焦点（`/去` 设置，落 `state.focus[targetKey]`）
- 默认路由（`routes`）
- 没有就明说，不猜

**方向 B：这个会话的回复是哪来的**（出站标记）
- 每条自动转发/`qq_send` 出去的消息，前缀带一个 ≤12 字的会话标签：`〔CMPOR·主分支〕`
- 只在「当前会话 ≠ 该 QQ 目标的默认绑定会话」时加，避免日常单会话聊天被污染
- 标签来源：工具执行时拿 `exec.agent.session` 反查（**待运行时验证**，见 §8 风险 R3）

因此「我引用的那条消息是谁发的」这个问题，插件自己就答得出来 —— 因为出站时它记下了 `message_id → sessionId`。

## 1. 现状缺口（已实测）

| 环节 | 文件 | 现状 |
|---|---|---|
| 路由 | `lib/deliver.js` `pickSessionId()` | 只读 `config.routes.{private,group}[id].sessionId`，静态表 |
| 入站 | `lib/poll.js` `handlePrivateMessages()` | 拿到 sessionId 直接 `deliver()`，**无命令层** |
| 投递 | `lib/deliver.js` `deliver()` | `ensureAgent()` → `followup`/`steer`；队列条目自带 `target`，**已支持一会话回多个对象** |
| 出站 | `lib/outbound.js` | 已经拿到 `message_id`（`noteReply` 在用），**记下 sessionId 只差一步** |
| 单向推送 | `lib/sendapi.js` | `POST 127.0.0.1:39273/send`，只写不读 |
| 进度数据 | — | **完全没有**，这是本次主要新增 |

数据源已经验证可用（详见调研笔记 §3）：

- `~/.dsh/storages/session_projcache.json` —— 112 个会话，每会话有
  `sessionStats{turns,steps,lastTurn,openStep,pendingCalls}` / `title` / `todos[]` / `goal` / `tokenUsage` / `contextPressure` / `permissions`
- `~/.dsh/storages/workspace.json` —— 48 个工作区，每项 `{path,title,sessionIds[]}`，另有 `global.archivedSessionIds`
- `ctx.agents.get(id)` —— 只返回**已经活着**的 agent，无副作用（判「是否真在跑」用它，判不到再退回投影启发式）

## 2. 方案总览

```
        ┌──────────── Phase 1（只读，先上）────────────┐
QQ ──▶ 命令层 ──▶ /进度 /看 ──▶ progress.js ──▶ projcache + workspace.json
        └──────────────────────────────────────────────┘

        ┌──────────── Phase 2（路由）─────────────────┐
QQ ──▶ 命令层 ──▶ /去 <n> /回  ──▶ focus.js（state.focus）
        │
        └─ 非命令 ──▶ resolveSession()
                       ① 引用命中 sentIndex
                       ② focus[targetKey]
                       ③ routes[target].sessionId
                       ④ 空 → 回提示，不投递
                          ↓
                     deliver()  ← 与今天完全一致，不动

        ┌──────────── Phase 3（可选推送）─────────────┐
ctx.on('session/event') ──▶ 关注的会话 turn/end ──▶ sendToQQ（带标签、限流）
```

**Phase 1 单独就能交付「了解某个工作区的某个会话的工作进度」**，且不动任何收发链路。
Phase 2 才是「我的消息能被别的会话处理」。

**v1 只做私聊。** 群聊继续走现有 `window.js` 那套攒批逻辑，一个字不改。
理由：群聊的入站有窗口/攒批/门控三套状态机，切会话会让 pending 和 `batchHolds` 指向错误目标（见 §7 R2）。私聊没有这些包袱，且用户的场景就是自己从手机发消息。

## 3. 模块设计

### 3.1 新增 `lib/progress.js` —— 只读进度聚合

```js
// 纯读盘 + 纯函数，不碰宿主服务，不唤醒任何会话
export function readWorkspaces()                  // → [{ id, path, title, sessionIds[] }]
export function readSessionDigest(sessionId)      // → { title, turns, steps, running, lastTurn,
                                                  //     todos:{total,done,current}, goal, tokens,
                                                  //     updatedSeq, hasData }
export function listProgress({ cwd, limit, includeIdle })  // → { running[], recent[], total }
export function describeForPrompt(sessionId)      // → 一句话摘要，给标签/推送用
```

判定「在跑」的两级（顺序不能反）：

1. `agents.get(id)?.status === 'running'` —— 权威，但只对活着的会话有效
2. 否则 `openStep != null || Object.keys(pendingCalls).length > 0` —— 投影启发式

⚠️ **绝不 `agents.resume()` 来读进度。** resume 会真的建出 agent，可能抢走 GUI 已打开会话的写句柄。读只用免副作用的路径。

⚠️ 投影缓存是 write-behind（`writeEveryEvents:200` / `writeIntervalMs:5000`），最多滞后 5 秒 + 200 事件。`/进度` 的输出里要注明「数据可能滞后几秒」，别让人以为卡住了。

### 3.2 新增 `lib/focus.js` —— 焦点表 + 引用索引

```js
export function focusOf(targetKey)                  // → sessionId | ''
export function setFocus(targetKey, sessionId, meta) // 落 state.focus，立即存盘
export function clearFocus(targetKey)
export function resolveSession({ cfg, kind, id, replyToId, targetKey })
                                                     // 按 §0.1 四级顺序，返回 { sessionId, via }
export function noteSent(sessionId, targetKey, messageIds)  // → sentIndex，带容量上限 + TTL
export function sessionOfSent(messageId)            // 引用路由用
export function tagFor(sessionId)                   // → '〔CMPOR·主分支〕' 或 ''
```

- `sentIndex`：`Map<messageId, {sessionId, at}>`，上限 500 条、TTL 6 小时（和 `outboundEntryTtlMs` 同量级但更长，因为人可能隔一阵才引用）。
- 出站两处写入：`outbound.js` 自动转发成功处（已有 `sentId`），`tool.js` 的 `qq_send` 成功处（已有 `messageId`）。
- `tagFor` 只在 `sessionId !== routes[target].sessionId` 时返回非空。

### 3.3 新增 `lib/commands.js` —— QQ 侧命令

命令在**插件内消费**，不进会话、不产生回合、不烧 token。

| 命令 | 别名 | 作用 |
|---|---|---|
| `/进度` | `/p` `/status` | 列正在跑 + 最近活跃的会话，按工作区分组，带编号 |
| `/看 <n>` | `/peek` | 只看一个会话的详情：todo 全文、最后一句、权限、上下文压力 |
| `/去 <n>` | `/go` | 切焦点到该会话（<n> 也可写 sessionId 前缀或标题片段，唯一匹配才算） |
| `/回` | `/back` | 清焦点，回到默认绑定 |
| `/在哪` | `/who` | 我现在在跟谁说话（焦点 + 默认绑定 + 最近引用目标） |
| `/帮助` | `/h` `/help` | 列命令 |

匹配规则：

- 只认**整条消息以 `/` 开头**且命令名精确命中；不认识的 `/xxx` 原样投给会话（别吞掉用户的话）
- 编号表存在 `state.cmdTable[targetKey] = { at, entries[] }`，**10 分钟有效**；过期就叫你重发 `/进度`，不猜
- 一次只认最后一条

### 3.4 改 `lib/poll.js` —— 命令拦截 + 路由解析

`handlePrivateMessages()` 开头插入：

```js
// 1) 命令：最后一条是命令 → 它之前的正文照常作为一批投递，然后执行命令
const cmdIndex = lastCommandIndex(messages, config.qqCommandPrefix)
if (cmdIndex >= 0) {
  if (cmdIndex > 0) await handlePrivateMessages(ctx, uin, messages.slice(0, cmdIndex))  // 递归深度 1
  const out = await runCommand(ctx, { kind: 'private', id: String(uin) }, messages[cmdIndex])
  await sendToQQ({ kind: 'private', id: String(uin) }, out)   // 命令回复走同一条唯一出口
  // 落到下面的游标推进，把整批标已读
  used = 'command'
} else {
  const { sessionId, via } = resolveSession({ cfg, kind:'private', id: uin, replyToId, targetKey })
  if (sessionId === '') { /* 回一句「没绑定，发 /进度 挑一个」并推进游标 */ }
  ...
}
```

关键约束（踩坑记录里已有的）：

- 命令回复必须走 `sendToQQ()` → `callOneBot()`，**不能另开出口**，否则绕过白名单
- 拦截必须在**游标推进之前**、`markIncoming` 之后（保住 `qq_close`/`qq_pass` 的回合账本语义）
- 命令执行完**仍要推进游标**，否则轮询会反复重投同一条命令

### 3.5 改 `lib/state.js` —— 持久化焦点

新增两段：`focus`（`targetKey → {sessionId, at, label}`）与 `cmdTable`。
自洁规则跟现有 `groups`/`privates` 一致：只保留仍在监听集合里的 key，其余丢弃并记日志。
⚠️ 不能用「不在 `groupUins` 就丢」来判私聊焦点 —— 私聊的保留集合是 `peerUin ∪ routes.private 的键`。

### 3.6 改 `lib/sendapi.js` —— 只读接口

新增 `GET /progress?cwd=<path>&limit=20` 与 `GET /progress/<sessionId>`。
给设置页和外部程序用，让「统一格式」先落地，不必等 QQ 命令层。

### 3.7 标签注入点（Phase 2 末）

- `lib/outbound.js` 自动转发：`text = tag + text`，`tag` 来自 `tagFor(sessionId)`；**只在非默认会话时加**
- `lib/tool.js` `qq_send`：同上（需 `exec.agent.session`，见 R3）

⚠️ 这里踩过的坑：**别写成整句提示**。曾经每条消息都带一段「想发表情就写 [表情:x]」的说明，几百条后纯烧 token 还让模型分不清谁说的话。标签只能是 `〔CMPOR·主分支〕` 这种 ≤12 个字符的裸前缀。

## 5. 实现后的工作流程（具体到每一句话）

### 场景 A：只想看看进度

```
你：/进度

机器人：
📊 正在跑 2 · 最近 4 · 共 112（数据可能滞后几秒）

▍CreateCMPOR
 1  主分支 (1)            第 204 轮 · 运行中
 2  评估算法重写           第 88 轮 · 闲置 3 小时

▍anything（视频插件）
 3  视频信息提取           第 3 轮 · 刚结束 2 分钟
    └ 最后：补丁已打上并验证，但宿主当前不会生效…

▍DSHPlugins
 4  ★当前对话 · QQ 桥接维护

回复 /看 3 看详情，/去 3 把话说给它
```

零 token、零唤醒；只读了两个 JSON。

### 场景 B：跟另一个会话说话

```
你：/去 3
机器人：已切到「视频信息提取」——你接下来发的话都进这个会话。
       发 /回 可以退出。

你：那个补丁重启后还生效吗
       └─▶ 进 session-xxx（视频会话），它跑一个回合
     〔anything·视频信息提取〕重启后需要重打，因为…
       └─◀ 自动转发回来，带标签指明是哪个会话说的
```

### 场景 C：不切焦点，靠引用

```
机器人（某会话主动推）：〔CMPOR·主分支〕build 挂了，要我改一下吗？
你：（长按引用这条，回）改
       └─▶ 引用命中 sentIndex → 直接回给 CreateCMPOR 那个会话，
           焦点完全没动，DSHPlugins 那边不受影响
```

这是最推荐的用法：**不用记编号，不用切状态。**

### 场景 D：多个会话同时找你

```
机器人：〔CMPOR·主分支〕build 好了
机器人：〔视频信息提取〕文档写完了
你：/进度                      ← 两条都在列表里，编号分别对应
你：（引用「build 好了」那条）辛苦了
       └─▶ 只回给 CMPOR
```

**不会因为谁最后说话就把你的下一句塞给谁** —— 这是和「最近会话兜底」最本质的区别。

### 场景 E：没配过任何东西（回归）

QQ 私聊 → `routes.private[uin].sessionId` → 和今天一模一样，一个字都不变。
命令层只是多了一个 `/` 前缀判定；不打 `/` 的消息走原路径。

## 7. 风险与已知坑

| # | 风险 | 处置 |
|---|---|---|
| R1 | **`agents.resume` 读进度会抢写句柄** | 读路径永远只用 `agents.get()` + 投影；resume 只出现在 `deliver()` 里（与今天一致） |
| R2 | 切焦点时群窗口里有 pending | v1 群聊不接焦点，天然不存在；若将来接，切焦点必须先 `flushPendingNow` 或丢弃并记日志 |
| R3 | `exec.agent.session` 是否真的在工具回调里可用 | **未验证**。先在 `qq_send` 里打一行临时日志实测；拿不到就退化成「只打日志不打标签」，绝不猜 |
| R4 | 投影缓存滞后 | 输出里注明；判「是否在跑」优先用 `agents.get().status` |
| R5 | 编号跨消息漂移 | `cmdTable` 带 10 分钟 TTL + 过期就要求重发，绝不按新列表解释旧编号 |
| R6 | 命令吞掉用户正常消息 | 只认整条以 `/` 开头且命令名精确命中；未知 `/xxx` 原样投给会话 |
| R7 | 加配置项漏改 `ui-wiring` | 按 skill §3 四处同改 |
| R8 | 会话在别的进程/被归档 | 复用 `archive.js` 的 `isArchived()`；归档会话不进列表、不接受焦点 |
