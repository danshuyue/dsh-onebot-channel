## 2. 建议实施顺序

```
0. 缓冲改造 ──┐
              ├─→ 3. 水群/潜水
1. 对话窗口 ──┘   （共用折叠组件、共用正文渲染）

2. 会话设定（独立，什么时候做都行）
```

| 顺序 | 为什么排这里 |
|---|---|
| **0. 缓冲改造** | 5 行代码的量，独立可测，先落地观察内存和 @ 上下文质量。它是水群的先决条件（§2.1 写明了不先改，「30 分钟窗口」就是假的） |
| **1. 对话窗口** | 改的是**已有行为**（@ 之后的沉默），越早暴露问题越好。而且用户感知最强——现在 @ 一句就哑，这个最难受 |
| **2. 会话设定** | 独立功能，无设定时零影响，风险最低，可以随时插入 |
| **3. 水群 / 潜水** | 最大、默认关、依赖缓冲和折叠组件。风险最高，最后做 |

同时改会互相干扰，回归测试也分不清是谁弄坏的。

## 3. UI 架构决策（三份文档共用）

### 3.1 不开新栏

现有 7 个标签在窄窗口已经挤，第 8 个会更挤（标签栏没有横向滚动）。

| 功能 | 放哪 | 理由 |
|---|---|---|
| 对话窗口 | **对话节奏** → 子卡「群聊连续对话」 | 调的是回复手感，跟分条/静默/合并是邻居；她仍是被叫才开口，不是主动行为 |
| 水群 / 潜水 | **主动搭话**（改名「主动开口」）→ 三张卡 | 用户心里它们是同一件事：「她会不会自己开口」 |
| 缓冲参数 | **高级** | 纯技术参数，这本来就是个收容所 |

### 3.2 先砍配置项，再谈放哪

原则：**「能调」≠「必须暴露」**。

- 调了也不会更好的 → **不做成配置，直接写代码常量**（连 `DEFAULTS` 都不进）
- 用户真的会调的 → 常显
- 介于两者 → 卡内折叠（`▸ 展开高级参数`）

砍完的结果：

| 功能 | 常显 | 折叠 | 不做配置（代码常量） |
|---|---|---|---|
| 对话窗口 | 5 | 1 | 4 |
| 水群 / 潜水 | 8 | 4 | 5 |

「不做配置」的那几个连 `DEFAULTS` 都不进，**不需要任何 `DELIBERATE` 白名单条目**。
只有「进了 `DEFAULTS` 却不给控件」的才要进白名单。

### 3.3 需要新增一个折叠组件

现有 UI 没有折叠模式——`qqb-adv` 只是 grid 布局（`client.js:86`）。
新增 `useState` 开关 + 条件渲染，约 20 行，**对话窗口和水群共用同一个**。

这是本轮唯一需要新增的 UI 模式。

## 4. 三份设计共用的技术前提

| 前提 | 影响谁 | 说明 |
|---|---|---|
| 正文渲染复用 | 对话窗口、水群 | `poll.js` 的 `stampOf` / `refOf` / `textOf`，别各写一份 |

## 5. 待修缺陷

### 5.1 `tests/capability-sim.mjs` 是红的

- 第 63 行断言封禁清单 14 项，实际 13 项（`add_custom_face` 已于 2026-10-27 放开）
- 第 247 行调 `sendQzoneMsg` 没传 `confirm` 直接抛错，后面用例全跑不到
- 该文件在 `test:legacy` 里，不在 `npm test` 链上，所以一直没暴露

### 5.2 群聊「前缀」输入框是死的

`client.js:627-635` 给群表也渲染了输入框，`api.js:215` 也照存，但群路径**从不读** `route.prefix`
——全仓库只有 `poll.js:251` 一处调用 `prefixOf`，是私聊路径。群头是硬编码的 `poll.js:395`。

**决定**：群聊确实不需要前缀，暂不修。但 UI 上还挂着这个输入框，用户填了会以为生效
——建议至少置灰或加提示（零成本降级）。

### 5.3 前缀不以「）」结尾会拼出畸形标记

填 `【阿明】` → `【阿明】·用户本人 QQ 123）`。`poll.js:257`。

## 6. 四条不能忘的红线

1. **对外动作一律默认关**。水群、潜水、主动搭话都是「拿用户的号说话」。
   唯一的例外是缺陷修复（对话窗口），因为它修的是已经发生的行为。

2. **绝不硬拼文案**。所有「她说什么」都交给模型判断，代码只负责「该不该叫醒她」。
   `proactive.js` 开头那段注释是这条红线的出处。硬拼一句「在吗」就退化成定时问候机器人了。

3. **「不说」是完整结局**。`qq_pass` 是正经出口，章程、注释、工具描述里都要写。

4. **静默失效是这个项目最大的敌人**。
   凡是用户可配的东西，保存时必须校验（正则、时间格式、fixed 时刻是否落在活动时间段内），
   错了当场报错，不要等到运行时不生效还没日志。
