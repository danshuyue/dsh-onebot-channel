## 2. 三条主链路（改功能前先认清自己在哪条）

```
【入站】QQ → WS/轮询 → poll.js 处理 → deliver.js → agent.followup 唤醒会话
                                    ↓
                              state.js 记游标 / merge.js 合并 / images.js 转图

【回合】会话里模型跑一回合，可能调 qq_send / qq_pass / qq_close / qq_wait

【出站】模型回复 → outbound.js 队列 → split.js 分条 → onebot.js 唯一出口
                                                  ↓
                                   allowlist 白名单 → blocked 封禁 → sensitive 审计
```

**关键约束**：所有出站都走 `onebot.js` 的 `callOneBot`，闸门就挂在那一个函数上。
想加新的发送路径，**必须**从 `callOneBot` 走，否则绕过白名单。

**`inject` 声明**（`lib/index.js:69`，少一个就会 `without inject` 抛错、功能静默失效）：
```js
export const inject = ['agents', 'tools', 'webServer', 'llm', 'sessions', 'attachments']
```
加新能力要读新服务时，**先在这里加名字**，再用 `ctx.get` / `serviceOf` 取。

## 3. 加配置项的标准动作（4 处，漏一处测试会红）

以新增 `fooBar` 为例：

1. **`lib/config.js`** → `DEFAULTS` 里加默认值（**这是唯一真相源**）
2. **`lib/api.js`** → `publicConfig()` 里暴露 + 归入对应的 `NUMERIC_FIELDS` / `BOOLEAN_FIELDS` / `STRING_FIELDS` / `ARRAY_FIELDS` / `ENUM_FIELDS`
3. **`lib/client.js`** → `setTunables({...})` 里加初始值 + 渲染控件
4. **`tests/ui-wiring.mjs`** → 若故意不给控件，必须加进 `DELIBERATE` 白名单并写理由

`tests/ui-wiring.mjs` 会同时检查：死配置（有默认值无人读）、可写字段是否都有控件、
API 暴露字段是否都在 `DEFAULTS` 里。**它比人眼可靠，别跳过。**

## 4. 踩坑记录（只留会咬人的）

> 完整版在 `docs/踩坑记录.md`（3 万字），这里只留「不知道就会重犯」的。

### 运行时（静默失效，最难查）
1. **群里 @ 了也不回** → 设置页只写 `routes.group`、没写 `groupUins`，群轮询压根没启动。
   修法：监听集合 = `groupUins ∪ routes.group`，每轮实时读。
2. **改了轮询间隔没用** → `setInterval` 在 apply 时把间隔写死。修法：自调度 `poll().then(schedule)`，每轮重读配置。
3. **协议端一卡，桥接永久哑** → `callOneBot` 没有超时。修法：`AbortSignal.timeout`（默认 8000ms）。
4. **协议端卡一次就雪崩** → `setInterval` 不等上一轮结束。修法：防重入 + 自调度。
5. **热重载后接口 404** → `webServer.register()` 的 disposer 没接住。修法：`ctx.effect(() => dispose)`。
6. **群里多出一段本不该发的正文** → 模型调了 `qq_send`，自动转发又把整段正文发一遍。
   修法：**同回合互斥** —— 用过 `qq_send` 且没报错就跳过自动转发，只有失败才兜底。
7. **插件装着但完全没反应** → 静态 `import '@deepseek-ai/dsh-tools'` 解析不到（官方包在 `app.asar` 里）。
   修法：**一律走 `inject` 服务，绝不 import 官方包**。

### 会话与消息（写坏数据）
8. **历史加载失败 `lacks an identified message`** → 手搓消息对象漏了 `id`，而 `session.append`
   **只校验形状不校验身份**，坏事件能安静落盘，下次读日志才炸。修法：`ensureId()` 强制兜底。
9. **设置页 0 个可选会话** → `inject` 少了 `sessions`，`ctx.get` 抛错被 catch 吞成 `[]`；
   且 `sessions.list()` 只返回活着的会话。修法：`inject` 加 `sessions`；列表 = live ∪ 扫盘。
10. **会话标题显示成 `#xxxx`** → 标题不是 header 字段，是日志里的 `session/title` 事件。修法：逐帧解 zstd。
11. **新建的会话在侧栏找不到** → `agents.create` 建的会话不登记进 `workspace.json`。
    修法：**别在插件里建会话**，在 DSH 里建好再回来绑。
12. **群友被当成用户** → 从没告诉过 agent 哪个号是用户。修法：`ownerUin` + 每条标「用户本人」/「群友（不是用户本人）」。

### 时序（协议端比 DSH 晚起来）
13. **重启后日志刷屏 timeout / 1006** → SnowLuma 的 OneBot 端口是**等 QQ 登录成功后才 listen** 的
    （实测差 ~2 分钟）。修法：探活门控 `health.js`，探通再起轮询和 WS；
    **但工具注册不押在探活后面**（出站能力与 QQ 登录无关）。
14. **设置页显示「插件出错」其实协议端只是没开门** → 连接类错误写进了 `lastError`。
    修法：错误分级 —— 连接类错误不写 `lastError`、不逐条刷日志，只在状态翻转时记一条。

### 前端与工程
15. **设置页整块白屏** → 函数组件里 `throw` 接不住，原来的「错误边界」也是函数组件。
    修法：真边界 = `class extends React.Component` + `getDerivedStateFromError`。
16. **组件里一个异常干掉整个面板** → 直接读没 inject 的服务会抛。修法：整段 `try/catch`，取不到就降级。
17. **配置和路由表莫名被清** → 配置曾放在插件目录，`file:` 依赖重装会覆盖。
    修法：数据全部搬到 `~/.dsh/qq-bridge.*`（**这条最重要，别再放回插件目录**）。
18. **跑 `sync.mjs` 报 EPIPE** → pnpm 对 `file:` 目录依赖是硬链接（同一 inode），整目录 cp 等于拷自己。
    修法：先判 inode，相同就跳过。
19. **游标用错字段会误杀新消息** → 私聊的 `message_seq` 是**两套编号混着的**（自己发的连续、
    对方发的跳号且不单调）。修法：群用 `message_seq`，**私聊用时间戳**；
    `message_id` 只做相等去重，**绝不比大小**（可能是负数）。

## 5. 排障：先看这四行日志

```bash
grep "\[config\]" ~/.dsh/qq-bridge-load.log | tail -1   # owner= 有没有 → 新版加载了吗
grep "\[poll\]"   ~/.dsh/qq-bridge-load.log | tail -3   # 群在监听吗、watch 到哪些群
grep "\[group\]"  ~/.dsh/qq-bridge-load.log | tail -5   # skip (no at)? 未配置会话? seeded?
grep "error"      ~/.dsh/qq-bridge-load.log | tail -5   # fetch failed = 协议端挂了
```

**一条铁律**：日志里可能同时有 DSH 和本地测试的输出。
`[module] loaded pid=… node=…` 那行能分清是谁在说话 —— **别把测试进程的日志当成线上故障**。

**确认运行的是哪版**：`curl -s http://<GUI端口>/api/qq-bridge/state` → `runtime.version` + `pid`。
版本没涨、启动时间还是上午 → 主进程仍在跑旧代码，**重启即可**，不用怀疑改错了。

**确认协议端通不通**（token 在 `~/.dsh/qq-bridge.config.json` 的 `token` 字段）：
```bash
curl -s -X POST http://127.0.0.1:3000/get_login_info \
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" -d '{}'
# → retcode:0 就是通了
```
⚠️ `get_friend_msg_list` **不存在**，`get_friend_msg_history` 才是对的。

**设置页入口消失**：拉 `/plugins/events`（SSE），看 `graph.entries` 里有没有插件 id ——
没有 = 没进 graph；有 = 进了但渲染崩了。

## 6. 发版与安装

**版本号规则**（用户定）：小修改 `+0.0.1`，功能拓展 `+0.1`。

**流程**（打包安装，验证真实分发形态）：
```bash
cd dsh-onebot-channel
node --check lib/*.js                       # 语法（client.js 是表达式，check 只验语法）
npm test                                    # 17 组模拟测试，必须全绿
npm pack --pack-destination ../dist         # 出 tgz
# 然后 plugin_manager install_bundle，target = tgz 绝对路径
```

**⚠️ 两个必知**：
- 换包后**必须重启 DSH** 才加载新模块代（`application: applied` 只代表装上了，不代表在跑）
- **同版本号不能重装**（`already-installed`）；要重装先 `remove_bundle`

**测试必须在隔离 HOME 下跑**：多数 sim 会改写真实的 `~/.dsh` 配置。
```bash
export HOME=/path/to/fakehome USERPROFILE='...' TMPDIR='...' TEMP='...' TMP='...'
```
`tests/assert.mjs` 与 `tests/pass-forward-sim.mjs` 相对安全，其余要隔离。

**不要**在插件里手改 profile 的 `package.json` / `cordis.patch.yml`，那是 `plugin_manager` 的事。
