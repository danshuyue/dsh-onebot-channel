## 1. 根因 A（最重）：「引用她」这条入窗规则在生产里是死的

`window.js` 的 `isWindowEligible()` 放行三类来源：触发人、@ 她、**引用她窗口内发过的消息**。
第三条依赖 `win.selfMessageIds`，而它只由 `noteReply()` 写入。

`tool.js:482` 的调用条件：

```js
if (target.kind === 'group' &&
    (Array.isArray(result?.data?.message_ids) ? result.data.message_ids.length > 0
                                             : Number.isFinite(messageId) && messageId !== 0)) {
  noteReply(...)
}
```

`sendToQQ()`（outbound.js:613）末尾无条件写
`output.data = { ...output.data, message_ids: sentMessageIds }`，
而 `sentMessageIds` **只有分条发送时才填**；单条发送时是 `[]`。

判据于是变成 `Array.isArray([]) ? [].length > 0 : ...` → `false` → `noteReply` 从不被调用
→ `selfMessageIds` 恒为空 → 「引用她」永远不成立。

**证据**：7454 那条她确实发了（群里可见），但窗口记录里 `selfMessageIds` 从未增长；
思念酱 7446 的 `reply_to=11591055` 正是她 7445 的 message_id，本该命中。
同一段代码在 outbound.js:1026 的自动转发路径上**写法是对的**（先取 `sentId` 兜底），
只有 qq_send 这一条漏了 —— 两条平行出站路，一条修过、一条没有。

**这是「对方接了她的话，她收不到」的直接原因。**

## 2. 根因 B：窗口资格里没有「正在跟她说话的人」

即使 A 修好，7441/7442/7444/7447/7449/7450/7453 这些**没有引用、也没有 @** 的接话仍然进不来。
`isWindowEligible` 只认「触发人」——本次触发人是用户本人（1321833118），
而实际对话方是思念酱（1836323387）。

设计稿 §3 明确写的是「**对触发者为主，但别人接话也算**」，
实现只落了一半：「别人接话」被压缩成了「引用她」一条窄路。

---

## 3. 根因 C：时间戳只到分钟，且上下文里没有她自己

- `stampOf()` 产出 `（2026-11-09 02:11）` —— **无秒**。两次发言间隔 15s / 20s / 45s
  在分钟刻度上全被抹平。她算不出节奏，只能猜。
- `fetchGroupHistory()` 与 `fetchGroupHistoryFor()` 都按
  `sender.user_id !== selfUin` **过滤掉她自己的发言**（poll.js:1280 / 1650）。
  于是上下文里只有「别人说了什么」，没有「我刚说了什么」——
  她无法形成「我说一句 → 对方接一句」的对话回合感，只能看到零散旁白。
- 窗口批次 `deliverWindowBatch()` 的正文同样不含她自己。

**这三条合起来，就是「她以为对方回得慢、一口气发几条」的成因**：
她看到的是「我的输出」与「别人的旁白」两团不相接的碎片，
而她自己的输出在她看来是「一次说完就没了」，于是把整段时间的空洞归因成「对方慢」。

## 4. 诊断包本身的缺口（用户第一条诉求）

`buildDiagExport()` 七节：`runtime / summary / config / state / outbound / log / dshLog`。

| 缺什么 | 现状 | 后果 |
|---|---|---|
| 投给模型的正文 | **完全没有** | 看不到她实际读到的上下文 |
| 聊天流水 | 只有插件日志，正文里一行 `skip (no at/window) seq=…` | 不知道漏了哪些话 |
| 工具调用参数 | `dshLog` 只有 `tool/result` / `execute.failed`，且**不带工具名** | 不知道她做过什么 |
| 她的思考 / 正文 | 无 | 不知道判断怎么来的 |

`collectDshToolEvents()` 的源码自己写着 `tool: ''`（「tool/result 宿主不记工具名」）。
而真正带工具名与参数的是**会话日志**里的 `tool/call` 事件 —— 本机实测可以解出来
（`session.v4.jsonl.zstd`，多帧 zstd，按 magic `28 B5 2F FD` 切帧，`title.js` 已有现成解码器）。

## 5. 修法（待用户确认后施工）

| # | 改动 | 文件 | 风险 |
|---|---|---|---|
| 1 | `noteReply` 判据改用与 outbound 同一套「空数组兜底 sentId」 | `tool.js` | 低，纯修正 |
| 2 | 窗口资格加一档：**窗口期内出现过发言的人**（`win.participants`） | `window.js` + `poll.js` | 中，需回归 `window-sim` |
| 3 | `stampOf()` 加秒（`HH:mm:ss`） | `poll.js` | 低，影响所有正文格式 |

| 5 | 诊断包新增 `conversation` 节：正文原文 + 聊天流水 + 工具调用（含参数）+ 最近 1~2 小时 | `api.js` + 新增 `diaglog.js` | 中，注意体积与隐私 |
