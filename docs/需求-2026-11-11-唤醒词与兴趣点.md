# 需求 · 群聊唤醒词与兴趣点

> 状态：**已交付 0.23.0**（2026-11-11 施工完成，见文末「变更记录」与 §8/§9）。
> 提出：2026-11-11。目标版本：0.23.0（功能拓展，+0.1）。
> 适用场景：群聊。私聊不涉及本需求。
> 关联：`docs/对话窗口-设计稿.md`（唤醒沿用窗口机制）、`docs/维护索引.md` §3（配置项五处同改）。

## 0. 一句话

- **唤醒词**：群里提到这个词 = 有人叫她一声，按 @ 那条链投递（但**不反向 @ 触发者**），提示词上明说「有人提到了你，去看看吧」。
- **兴趣点**：群消息命中关键词 → 记下并**等 N 分钟**再回去看那段时间的聊天 → 交给独立 LLM 判「这是不是主人真正关心的那类事」→ 命中才私聊通知主人。

两条都是**旁路**：判定/等待绝不阻塞群消息主链路。

## 1. 唤醒词

### 1.1 配置

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `wakeWords` | string[] | `[]` | **空 = 功能关闭**。全群共用一张词表，所有监听群同样生效。 |

设置页：**一个多行输入框**，逗号（中英文）或换行分隔。界面里放两个占位提示：`大肥鱼`、`肥鱼,阿鱼`（虚子，仅作示例，不写进配置）。

**护栏（保存时校验，不合规直接拒绝并回显原因）**

1. 单词长度 < 2 → 拒绝。单字（`鱼`、`你`）在任何群聊里都会误伤，等于把整个群变成 @ 她。
2. 去重后保存；词内首尾空白裁掉。
3. 唤醒词**不能等于她自己 QQ 号或名字**的字面（避免和 @ 重复判定）。
4. 上限 20 个词。

### 1.2 命中判定

判据用**纯文字段**（`textSegmentsOf`），不用 `textOf` —— 后者把 at 段渲染成 `@3566906627`，会让「@ 她 + 大肥鱼」判成「正文里有大肥鱼」而重复计数（同 `poll.js:809` 那条忽略指令踩过的坑）。

匹配方式：**子串包含**（`text.includes(word)`），不做词边界。中文没有可靠词边界，且用户举的例子（「大肥鱼」）本身就希望被「大肥鱼好可爱」这种上下文命中。唯一的成本是「肥鱼」可能命中「肥鱼腩」，接受——用户可自行把词写长一点。

新模块 `lib/wake.js`（纯函数，零依赖，好单测）：

```js
export function matchWakeWord(segments, words)  // → '' | 命中的词
export function normalizeWakeWords(input)       // → { words, rejected: [{word, why}] }
```

### 1.3 与 @ 的三处差异（必须同时做，缺一处就是「说好不 @ 结果 @ 上了」）

唤醒**沿用 @ 的整条投递链**（带上下文、引用原消息、开窗扣额度），差异只有三点：

| # | 位置 | @ 的行为 | 唤醒的行为 |
|---|---|---|---|
| 1 | 入队判定 `poll.js:819` | 窗口开着也会被 `shouldQueueForWindow` 收进队列等攒批 | **不进队列**，直接投递（相当于「叫一声」，不能让她等 8 秒） |
| 2 | 首句自动 @ `poll.js:1164` | `atMe && senderUin !== selfUin` → `atUin = senderUin` | `atUin = ''`（不 @ 回去） |
| 3 | 窗口内自动 @ `window.js:301` `atUinForWindow` | 开窗后前 2 条回复 @ 触发人 | **唤醒开的窗口不 @**（`win.openedBy === 'wake'` 时恒返回 `''`） |

第 3 条最容易漏：`openWindow` 之后 `win !== null`，`atUinForWindow` 会在 `repliesInWindow < WINDOW_AT_REPLIES(2)` 时把 `senderUin` 返回回去——于是「不 @ 触发者」在第二句就食言了。**必须给窗口记录加 `openedBy: 'at' | 'wake'`**，开窗时写入，`resetRecoveredWindows` 恢复时兼容老记录（缺省 `'at'`）。

引用（`replyTo`）**保留**：引用不是 @，它只是「这条在回哪一句」，对定位有帮助。

### 1.4 提示词放大

投递正文头部（`head` 之后、正文之前）追加一行，走模板配置：

| 键 | 默认 |
|---|---|
| `wakeNoteTemplate` | `（群里有人提到了你（「{word}」），相当于叫你一声 —— 去看看吧，不用 @ 回去。）` |

占位符 `{word}` = 命中的词。空串 = 不加这一行。

为什么不用 `prompt.js` 的常驻段落：那是**系统段落**，对所有会话生效；唤醒是一次性事件，写进那一条消息的正文才不污染上下文，也不烧每轮 token。

### 1.5 护栏（防刷屏）

唤醒和 @ 一样消耗开窗额度（`windowPerGroupDaily`），但有额外一层：

| 键 | 默认 | 说明 |
|---|---|---|
| `wakePerGroupHourly` | 3 | 同一群 1 小时内最多被唤醒 N 次，超出只记账不投递。`0` = 不限。 |

判据：理由同「@ 是同步唤醒、不带 @ 要攒批」—— 唤醒词比 @ 便宜得多（不用切输入法找人），群里玩起来会连喊。没有这层，一个词表能把她的窗口额度在十分钟内烧完。

一次消息里**同时 @ 和命中唤醒词**：只算一次，`atMe` 优先（日志标 `at=true wake=大肥鱼`，便于核对）。

### 2.1 配置

总开关与全局参数：

| 键 | 类型 | 默认 | 说明 |

| 字段 | 类型 | 说明 |
|---|---|---|

| `groupUins` | string[] | 生效群；空数组 = 所有监听群 |

### 2.2 时间轴

```
        ┌── preMinutes ──┐ 触发点 ┌── waitMinutes ──┐ 到点
 ───────┼────────────────┼────────┼─────────────────┼────────►
        回看的聊天      关键词命中  等待期（继续收）    送判
```

三段的取材方式**不同**，这是设计的关键：

| 段 | 来源 | 为什么 |
|---|---|---|
| 触发前 `preMinutes` | 命中那一刻从**内存缓冲**切快照 | 缓冲立即被新消息挤掉，必须当场存；只有 10 分钟，内存里一定有 |
| 等待期 `waitMinutes` | 等待期内每条该群消息**追加进任务并落盘** | 判定依据里最关键的「有没有人跟进、真崩了没有」全在这段 |
| 补充 | 到点后可选拉一次 `get_group_msg_history` | 只作补齐，**不作为主路径** |

⚠️ **不依赖协议端历史锚点**：`get_group_msg_history` 的 `message_id` + `reverse_order` 语义在 SnowLuma 上没有实测过「取触发点之后」，拿它当主路径会得到一个安静的空窗口（听起来像「没有后续消息」，实际是拉错了方向）。任务里自带 pre + during 就够了。

内存缓冲不够用时（`GROUP_BUFFER_LIMIT = 30`，`poll.js:155`）：命中那一刻只回看 `preMinutes`（默认 10 分钟），30 条在多数群里够用；不够时按实际收到的为准，并在送判 prompt 里注明「开头可能不全」，**不谎称完整**。

### 2.3 任务落盘

`~/.dsh/qq-bridge-interests.json`（沿用 `env.js` 数据目录约定，新增 `interestsPath()`）：

```jsonc
{
  "tasks": [
    {
      "id": "t-<epoch>-<rand>",
      "pointId": "p-xxx",
      "groupId": "716197431",
      "groupId_name": "测试群",
      "triggerSeq": 512,
      "triggerMessageId": "-2123597213",
      "triggerUin": "1321833118",
      "triggerNick": "群友A",
      "triggerText": "服又崩了",
      "triggerAt": 1762800000000,
      "dueAt": 1762800600000,
      "pre":  [ { "at": 0, "uin": "", "nick": "", "text": "" } ],
      "during": []
    }
  ],
  "recent": [ { "fp": "<sha1>", "pointId": "p-xxx", "groupId": "", "at": 0 } ],
  "daily": { "2026-11-11": { "calls": 0, "perGroup": { "716197431": 1 } } }
}
```

为什么必须落盘：`dueAt` 在 10 分钟后。这中间可能热重载、可能协议端断线、可能 DSH 重启 —— 只要任务丢了，主人那次「帮我盯着」就静默失效，而**没有任何人会发现**。启动时扫一遍 `dueAt` 已过的任务，直接进队列。

写盘节流：`during` 追加时按 5 秒合并写一次（同 `poll.js` 心跳节流的做法），任务结束立即写。

### 2.4 判定器：为什么直连 LLM，而不是子代理

**结论：判定直连 LLM；「让 AI 组织语言再下发」用主会话投递，不用子代理。**

| 维度 | 直连 `ctx.llm.stream()`（选定） | 子代理 `subagents.startActivation()` |
|---|---|---|
| 成本 | 一次 200–400 token 的分类调用 | 一个完整 agent loop（可多步、可调工具），贵一个量级 |
| 时序 | 独立于群会话，群会话正忙时照跑 | 挂在会话上，群会话跑回合时启动要排程/排队；10 分钟窗口会漂移 |
| 取结果 | `for await (chunk)` 直接拿到文本 | `delivery: 'parent'` 是**投递型**，结论回到父会话，插件还得回去读会话日志（zstd 多帧）才能拿到 —— 多一层脆弱链路 |
| 复用 | 天然共用宿主已配的 provider 与凭据 | 同样共用，但代价更大 |

**「共用 key 和 url」天然满足**：`ctx.llm.stream({ provider, model, ... })` 走的就是宿主这一层已配置的 provider 与凭据。插件**不存任何 key**，也不读任何配置文件——这是本项目一贯的立场（`deliver.js:117` 那条「一律走 inject 服务，绝不 import 官方包」同理）。

**「扫描当前模型列表」已实测可行**（2026-11-11，照 `dsh-cost-meter/lib/model-labels.js:13` 的写法核过）：

- `llm.listProviders?.()` 返回 `[{ id, name }]` —— provider 枚举**有**；
- `llm.listModels(provider)` 返回 `[{ id, name }]` —— 逐 provider 的模型列表**有**。

所以设置页直接两级下拉（provider → model），并保留「手填」兜底。实现按探测式写，缺哪个接口就退一级：

1. `listProviders()` 有 → provider 下拉；没有 → 只列 `agentOptions.provider` 一个，其余靠手填；
2. `listModels(provider)` 有 → model 下拉；没有 → model 手填；
3. 都拿不到 → 两个文本框，默认值继承 `agentOptions`；
4. 无论哪条路，都给一个「试跑一次」按钮：真实发一次最小调用，把延迟、返回的模型名、token 用量打回界面。

这样「能扫就扫，扫不到也能用」，不会因为宿主版本差异让整块配置失效。

### 2.5 判定 prompt 与输出契约

System：

```
你是主人的关注点判定器。给定一个「关注点描述」和一段群聊记录，判断这段聊天里
是否真的出现了主人关心的那类情况。严格按描述的字面意图判断，不要放宽：
如果描述关心的是「服务器崩溃的反馈」，那么「昨天我的程序崩溃了」不算，
「XX 服又炸了、进不去了」才算。拿不准就判 false。只输出 JSON，不要解释。
```

User：兴趣点 `label` + `description` + `keywords` + 群名/群号 + 时间段 + 逐条消息（`HH:mm:ss 昵称(QQ): 内容`，她自己说过的话标「你自己」，与 `deliverWindowBatch` 的渲染口径一致）。

输出契约（`response_format` 不可用时靠 prompt 约束 + 容错解析）：

```json
{
  "match": true,
  "confidence": 0.0,
  "summary": "一句话说清发生了什么（≤60 字）",
  "keyMessage": { "time": "2026-11-11 03:41:12", "nick": "群友A", "uin": "1321833118", "text": "原话（≤200 字）" },
  "related": [ { "nick": "", "uin": "", "text": "" } ],
  "reason": "为什么算（≤80 字）"
}
```

解析：先 `JSON.parse` 整段；失败则从 ```json 代码块 / 第一个 `{` 到最后一个 `}` 抠出来再试；再失败判 `match=false` 并记一行日志（**判定失败不等于命中**，宁可漏报不误报）。

调用形态（**已按 `ds-bot/src/host/btw.js:163` 的实测范式核过**，不是猜的）：

```js
const messages = [
  { role: 'system', content: [{ type: 'text', text: SYSTEM }] },
  { role: 'user',   content: [{ type: 'text', text: USER }] }
]
for await (const chunk of llm.stream({
  provider, model,            // 来自 interestJudgeProvider / Model，空则继承 agentOptions
  messages,                   // 裸对象，不是 session.append 的 message
  maxTokens: 800,
  temperature: 0,
  sessionId: `interest:${taskId}`,   // 只用于计费归因，不写任何会话
  signal: AbortSignal.timeout(60_000)
})) {
  if (chunk.type === 'text-delta') out += chunk.text
  if (chunk.type === 'finish' && (chunk.reason.kind === 'error' || chunk.reason.kind === 'aborted')) return failed
}
```

chunk 类型（实测齐全）：`text-delta` / `reasoning-delta` / `tool-call-delta` / `usage` / `finish`。
判定只要 `text-delta` 拼串；`finish.reason.kind === 'max-tokens'` 视为「输出被截断」→ 当失败（JSON 必然不全）。

全局并发 1（一个简单队列，避免 10 个兴趣点同时炸）。`temperature` 若目标模型不接受会被适配器忽略，不影响主流程。

### 2.6 命中后的两条下发路（两个独立复选框，可同时开）

格式化正文（两条路共用同一份素材）：

```
【群名】[群友A]：「服又崩了」
时间：2026-11-11 03:41（群 716197431）
概述：有人报服崩，另有两名群友跟进确认进不去。
关注点：服务器崩溃反馈
原话：03:41:12 群友A：服又崩了 / 03:42:05 群友B：我也进不去
```

- `【群名】` 取 `groupNames.get(groupId)`，拿不到写 `群 <id>`。
- `[群友A]` = 触发那条的昵称。用户要的格式 `【群昵称】[群友]：「内容」` 就是这一行。

**路 A（`interestNotifySelf`，默认开）**：`sendToQQ(privateRouteTarget(), text)` —— 与 `outbound.js` 的 `relayGroupReport` 同一个出口、同一套白名单/审计。失败吞掉只记日志（通知是附加行为，不能反过来影响判定链）。

**路 B（`interestNotifySession`，默认关）**：`deliver(ctx, ownerPrivateSessionId, 素材, { kind:'private', id: ownerUin })` —— 把素材作为一条用户消息投进**主人的 DSH 私聊会话**，由那边的 agent 组织语言。正文随后经 `autoForwardPrivate`（默认开）自然到达 QQ 私聊。

路 B 的三条纪律：
1. 素材首行必须写明「这是插件上报的兴趣点事件，不是主人在说话」，否则主会话会以为主人在跟自己聊天、反过来问她。
2. 投递目标只取**主人私聊会话**（`privateRouteTarget()` 对应的 sessionId），**绝不兜底**到别的会话 —— 复用 `deliver.js` 已有的「归档就放弃、不兜底」逻辑。
3. 两条路同开时可能双份：路 B 的文案由模型生成，内容会与路 A 重叠。这是用户明确要的（复选框），但在设置页文案里写清楚「两个都开 = 可能收到两条」。

### 2.7 去重与额度

三层，按顺序判，任一层不过就丢弃：

1. **冷却**：同 `pointId` + 同群，`now - lastNotifiedAt < interestCooldownMinutes` → 丢。
2. **内容指纹**：`sha1(pointId|groupId|规范化后的 keyMessage.text + related 前 2 条)`，`recent` 里 24 小时内有同指纹 → 丢。防「同一个崩溃被不同的人复述 5 遍」。
3. **额度**：`daily.perGroup[gid] >= interestDailyMaxPerGroup` → 丢，并记一行「超额度，已丢弃」。

另有成本硬顶 `interestDailyMaxCalls`：**送判之前**判，超了就不调用模型（省的是钱，不是消息）。

### 2.8 失败降级（整条链的共同纪律）

- 判定失败 / JSON 坏 / 超时 → **不通知**，记一行日志。宁可漏报。
- 路 A 发送失败 → 吞掉，只记日志。
- 路 B 投递失败 → 吞掉，只记日志。
- `interest.json` 读写失败 → 内存态继续跑，下次写重试。
- **任何环节都不向 `handleGroupMessageCore` 抛错**：命中关键词后只做「入队任务 + 落盘」，`await` 到此为止，等待与判定全部 fire-and-forget。

## 8. 施工中发现并修复的既有缺陷（0.23.0 顺带交付）

> 这一节记的是**不在本需求范围内**、但挡住交付的问题。修它们没有改变任何行为，
> 只是让「本来就该跑的测试」真的能跑起来。

### 8.1 变异脚本用 `spawnSync` 默认管道 → 本机 EPERM，读到 0 字节（坑 28 的教科书形态）

**症状**：`crowd-hint-mutation` / `report-relay-mutation` / `autoforward-mutation` /
`notice-wait-mutation` 的 baseline 全红，而且**一条 ✗ 都没有**、输出空白。

**实证**（不是推断）：

```
① 管道: status=null | stdout=undefined | stderr="" | error=EPERM
② 文件: 内容="hello-file"
```

同一个命令，走管道 EPERM，走文件重定向正常。**这不是被测代码坏了，是一个字节都没读到。**

**为什么一直没被发现**：这 4 个脚本从来没进 `npm test` 链（`test:raw` 里没有它们），
所以「在本机跑不通」这件事从来没有机会暴露。

**修法**：全部改成 `stdio: ['ignore', fd, fd]` + `readFileSync` 读回。

### 8.2 变异脚本原地改真实源码 → 沙箱 EPERM；且崩溃时会留下被改坏的源码

**症状**：`window-queue-all-mutation` / `group-self-context-mutation` / `diaglog-mutation` /
`self-reply-eligible-mutation` / `window-batch-render-mutation` 报「变异构造失败：EPERM」。

**根因**：这几个脚本用 `mutate(真实路径, ...)` 改**真的** `lib/*.js`，跑完再 `restore()` 还原。
DSH 沙箱把工作区源码设成只读 → 改不动。

**比「跑不通」更严重的**：`restore()` 在崩溃 / 被 kill / 进程被超时杀掉时**不执行**，
于是源码留在被改坏的状态。下一次跑测试就是对着坏源码跑，而报错看起来像别的问题 ——
**这是会真正污染仓库的失败形态**。

**修法**：先 `cpSync` 一份插件到临时目录，在副本里变异、跑副本里的测试。真实源码**只读不写**，
崩溃也不会留下脏状态。baseline 也改在副本上跑（否则它可能对着被改过的源码跑）。

### 8.3 `tests/ui-wiring.mjs` 的切片锚点被新代码撞上（假红）

**症状**：加了 `interestPoints: [...].map(function (row) { ... })` 之后，
「可写字段都进了设置页的表单状态」报缺 10 个键。

**根因**：切 `setTunables({...})` 那段源码用的是「从 `setTunables({` 切到它之后第一个 `})`」，
而 `.map(...)` 自己的收尾 `})` 把切片**提前截断**了。

**修法不是放宽断言**（那是把看守拆掉），而是换一个真正稳的判据：
从 `{` 起按**花括号深度**数到回 0。仍是同一个方向的看守，只是不再脆弱。
